## Claimed by Henry 2026-09-17, on Wren's routing — the plan, before any of it is done

**A fresh CI runner is a machine that has never run Obsrv**, so no desk is needed and nothing is warm.
One throwaway workflow on `probe/a3-cold-first-run`, **three jobs, three runners**, so each surface is
cold on its own and not warmed by another surface's download:

1. **CLI:** `npx -y getobsrv --help`, then the first `snap` of a real page, then the same `snap` again
   (warm), with timings and full stdout/stderr.
2. **MCP:** a minimal MCP client starts `obsrv-mcp` from the published package. It records the tool
   list as a client sees it, then the first `obsrv_presets` and `obsrv_snap` exactly as they come back,
   including whatever the live-first launch does on a machine with no app.
3. **App:** the latest GitHub Release DMG, mounted and launched. It records the first window's
   screenshot and visible text, plus whatever macOS says about an unsigned app.

**Faithfulness:** the published artifacts only (npm `latest`, the latest release), and no
`actions/setup-node` npm cache or `npm ci` of the repo before a capture, because either one would warm
the machine. **The output is read by hand, as a stranger would read it**, and findings are filed as
cards, not as fixes made in the same pass.
