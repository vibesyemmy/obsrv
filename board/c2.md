## Claimed by Rook 2026-09-16, assigned by Wren

### What "by rule" can and cannot mean here, decided before writing any of it

`docs/compatibility.md` already states the rule, and `docs/breaking-changes.md` already keeps the
register. **What is missing is not a rule; it is something that fails when the rule is not followed.**
Today the register is kept by whoever remembers, which is the definition of "by habit" — and the card
already names the case that habit missed: `url` changed meaning for live callers in 0.59.0.

The register's own definition is what makes a check tractable:

> a field that disappears or is renamed, a value that moves to a different key, a new value in an
> enum a caller may have cached, or a field whose *meaning* changes while its name stays the same

and, decisively:

> on the MCP surface, **adding** a field is breaking, because every output schema is
> `additionalProperties: false`

**So on the MCP surface every shape change is breaking, in both directions.** A check does not have
to judge severity — it only has to notice that the published shape moved, which is exactly the
comparison `src/shared/keyPaths.ts` already performs and `#127` already made server-side.

### The shape

1. **A committed snapshot of the public shape** — the key paths of every MCP tool's published
   `outputSchema`, read from the server's own `tools/list` (as `publishedPaths()` does, so "public"
   means what a client actually receives rather than a second conversion of the same zod), plus the
   CLI's JSON keys.
2. **A unit test** that recomputes it and fails when it differs from the snapshot, naming the paths
   that appeared or vanished.
3. **A CI check** that fails when the snapshot changed and `docs/breaking-changes.md` did not — the
   "in the same change" half, which a unit test cannot see. Same shape as `ci.yml`'s `scope` job,
   which already reads `git diff --name-only`.

### The controls, and the third is the one that matters

- **Change a field without a register entry → red.** Both arms: the unit test on the shape, the CI
  check on the missing entry.
- **Add the entry and update the snapshot → green.**
- **VACUITY ARM, and the reason this card could go wrong:** a change the check cannot see **must not
  read as "no breaking change"**. `bug-orientation-name` (Backlog 27, also C2) is exactly that case —
  a field that keeps its shape and changes its meaning. The shape diff is blind to it **by
  construction**, and no amount of care fixes that.

  **So the check must be named for what it measures, not for what the card wants.** It is a
  *public-shape* check, not a *breaking-change* check, and its green must say "the published shape
  did not move", never "nothing breaking happened". A green that reads as the second is the exact
  defect this board has spent the day finding: an instrument whose silence is taken for a verdict it
  never gave.

### For Henry, and not for me

**Whether a meaning-only change should also be gated, and how.** The shape diff cannot do it; the
options are a register entry required for every release regardless (cheap, and mostly noise), or
nothing and a documented blind spot. `bug-orientation-name` is the worked example to argue it
against. I would take the documented blind spot and say so loudly in the check's own output, but
that is a call about how much ceremony the project wants, not a measurement.
