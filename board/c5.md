**The standing record is `docs/note-inventory.md`** (merged, 856d268). It lists 17 live-surface notes
with 3 observed, and 41 headless/MCP call sites that were never hand-checked. Its line numbers are
from 2026-09-14.

**The ground has moved.** A mechanical count on `main` (`bf81217`) finds 123 call sites that push to
`warnings`/`notes` (cli 65, mcp 37, main 18, preload 3), against 58 then. Many push the same sentence
from a shared builder. So:

1. **Re-inventory by producer, not by call site.** List each distinct sentence (a `src/shared` note
   builder or an inline literal), which surfaces emit it, and where. That's mechanical, and it says so.
2. **Hand-check each producer against the suite.** The question is whether an e2e run against a page
   produces the state, not whether a test mentions the text: the phrase sieve undercounts, as the
   09-14 pass measured. Only what was read by hand gets recorded.
3. **For each unobserved note, pick one of three:** a fixture that produces it, observed on CI (live on
   the runner, whose offscreen target renders; no desk); a finding that the state can't be reached,
   and then the sentence is proposed for removal; or a named reason it stays unobserved.

**Deliverable per step:** `docs/note-inventory.md` updated in place, in board-sized PRs, never as one
large change.
