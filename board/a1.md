## THE CI IDENTITY CHECK, BUILT, 2026-09-20 by Kenya — the engineering half, not the decision half

**Re-verified `chore/signing` (`f3fdbe9`) still merges clean on today's main** (1534 commits since
the base, real `git merge --no-commit`, not `merge-tree`'s summary) rather than trusting the last
figure. It does, no conflicts. Branch `chore/signing-ci-identity-check` carries that merge plus the
step below, PR up.

**Built Rook's proposed identity assertion (line 32 of this card), with one change.** Rook's design
named the expected string directly: `"Developer ID Application: Voicify Limited (NDXPR623CF)"`. I did
not write that into the workflow. **Which entity signs the app is the identity decision this card
already says is Opeyemi's** (§3 below, "unanswered and is a decision, not a task") — hard-coding
Rook's draft answer into CI would have made the engineering half quietly decide the product half.

Instead: a new secret, `SIGNING_IDENTITY`, holds the exact `codesign` authority string. The new step
(`.github/workflows/ci.yml`, gated `HAS_SIGNING == 'true'`, same as the rest):
- runs `codesign -dv --verbose=4` on every `.app` this build produced (found by walking `dist/`, not
  by naming electron-builder's per-arch folder, since that's its convention to change) and fails
  unless the authority line **equals** `SIGNING_IDENTITY` — Rook's own principle, "assert what it
  must EQUAL, never 'is signed'";
- runs `spctl -a -vvv -t install` on the same and requires `source=Notarized Developer ID`;
- runs `xcrun stapler validate` on every `.dmg`, since docs/signing.md §4 already knew a verified-but-
  unstapled signature still shows the damaged-app dialog;
- **fails if `HAS_SIGNING` is true and `SIGNING_IDENTITY` is unset**, rather than skipping. An unnamed
  target and no check are the same silent gap this step exists to close, so the identity decision
  must be made (by setting the secret) before a signed release can ship — the workflow enforces that
  the decision happened without making it.

**Verified by running the actual logic, not by reading it.** No cert on this machine and no CI run to
spend, so `codesign`/`spctl`/`xcrun` were stubbed on `PATH` and the extracted script run against five
scripted scenarios: correct identity end to end (2 apps, 2 DMGs, passes); wrong identity (`Restack
Dev`, the real historical failure) — reds, names the file; `SIGNING_IDENTITY` unset — reds before
touching any file; no `.app` found under `dist/` — reds rather than silently checking nothing; right
identity but Gatekeeper says un-notarized — reds. All five gave the exit code and message intended.
YAML parsed with `js-yaml` (7 jobs, step present, `if`/`env` as written) and the embedded script
passed `bash -n`.

`docs/signing.md` §5 gets the new secret and a paragraph on what it gates.

**What is still not done, unchanged from before this pass:** the p12 import (needs Opeyemi's
password) and the identity decision itself (needs the `SIGNING_IDENTITY` value, which is his to
choose). **Also newly true:** this check has never run against a real signed build — the stub run
