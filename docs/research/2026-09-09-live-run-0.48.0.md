# 0.48.0 driven against five more live sites

The seventh run, on a stack that is 0.48.0 end to end, against
paulgraham.com (a responsive list on the phone and the classic table
layout on the laptop), shopify.com (cover-fit marketing imagery),
lemonde.fr (a consent card over a dark scrim, thin serif, hairlines),
developer.apple.com/documentation (an app-shell docs site with an inner
scroller) and booking.com (a dense grid behind a geo redirect, rendered on
the client). theverge.com got one probe for the error-text fix and
textfiles.com stood in as the page with no viewport meta, since Paul
Graham's site has been redesigned. Headless, live, and every surface. The
site is the fixture; this reports on the tool.

## Held

- **The five 0.48.0 fixes, on real pages.** The Verge's refusal is one line
  through the session's server: "obsrv lint failed (exit 1): obsrv: load
  did not finish within 20000 ms …". Shopify's hero at a phone is judged by
  its fit — "828×466 px covering 720×1273 device px (object-fit: cover):
  upscaled 2.73×" — and Apple's card images by theirs, downsampled 3.26×
  under a cover fit. On textfiles.com at `android-65`, laid out 980 wide and
  drawn at 0.3673, the audit's own rect for a link went through
  `highlight { space: "page" }` and came back drawn at 132, 802, 161×20 —
  the rect times the scale times the density, on the link — and `inspect
  { at }` given the drawn centre of a heading found the heading, its
  layout-scale note said once, in the readout.
- **The rest of the surface.** The docs shell's inner scroller was walked
  (9 screenfuls, 7,674 px) and its dark UI judged on Budget TN (136 pairs
  that pass as stated and fail on the panel). The coverage note fired
  honestly on booking.com's growing page. `report` wrote both Paul Graham
  screens, said the phone's 15,444 px page was captured to the twelve-band
  cap, and the diff on the laptop named seven bands losing ink. `diff` on
  the Apple docs settled with one band finding.

## Broke or misled, ranked

1. **An empty document is measured and reported as a clean page.**
   booking.com at `iphone-61`, headless: `targets.count: 0, text.count: 0,
   pageHeight: 852` — one viewport, nothing on it — with `warnings: []`.
   The lint answers the same, all six rules at zero. A snap of the same
   URL in the same run shows the full mobile page, because a render waits
   for paints to go quiet and a measurement runs the moment the load and
   the walk are done; booking's mobile document is empty at `load` and is
   rendered by script inside the next second: with `waitMs: 1000` the same
   audit measures 72 targets and 89 text elements, with 5000, 105 and 223 on
   a 3,746 px page. Three signals were in hand — no text, no targets, a page
   exactly one viewport tall — and nothing was said. This is the
   measurement's version of the blank frame 0.47.0 fixed for captures: a
   document with no text at all should be held for a grace and, if still
   empty, answered with a warning that says nothing was there to measure.

2. **A background painted by a layer that is not an ancestor is invisible
   to the contrast rules.** lemonde.fr's consent wall puts "Reject all
   cookies" in `#eff0f3` on a fixed dark scrim; the lint and the inspector
   both say "#eff0f3 on #ffffff is 1.14:1 as stated", `backgroundNote:
   "computed"`, and fail it. The PNG's pixels under the words are
   (41, 42, 43): the pair is about 13:1 and passes. The walk up the
   element's ancestors, compositing translucent layers, reaches the body's
   white; the scrim is a sibling branch painted beneath the text, and the
   walk never looks sideways. The same walk can pass text that a scrim
   makes unreadable. `document.elementsFromPoint` at the text's box gives
   the stack that is actually painted there; the first opaque background
   below the text in that stack, with the translucent ones above it
   composited, is the background someone sees.

3. **Spacer GIFs flood the upscaled rule and spend the image cap.** Paul
   Graham's desktop layout is a 1998 table: the lint at `laptop-768` found
   332 upscaled images — "1×1 px stretched over 26×1 device px: upscaled
   26× on its width" — and reported 206 more images counted but not
   measured. A 1×1 file stretched into a gap is a spacer, not a picture,
   and nothing about it is blurred; on such a page every real image falls
   past the cap behind them. Files of a pixel or two on a side should be
   left out of the image rules, counted under `skipped` with a word.

## Fixed on `fix/empty-document-and-painted-background`

1. **An empty document is held for, then said.** A measurement whose
   report has nothing in it — no target and no text for the audit, no text,
   edge or image for the lint — is re-asked every quarter second for three
   seconds (`shared/emptyDocument`, the measurement's version of the blank
   frame rule). A page that fills in that time is walked again, since the
   walk saw an empty page, and measured; one that stays empty is measured
   as it is, with a warning first in the list: "nothing to measure: the
   page had no visible text and no targets 3 s after it loaded — a page
   rendered by script that had not run yet, a bot wall, or an empty
   document …". The CLI and the app's control `audit` and `lint` share it,
   so the live MCP answers carry it too. booking.com at `iphone-61` with no
   wait now measures 70 targets and 88 text elements, and the coverage note
   says honestly that the page grew behind the walk.

2. **The background is what is painted under the text.** Both page scripts
   take the stack at a point inside the text's box (`elementsFromPoint`),
   from the element down, and use the first opaque background in it with the
   translucent layers above composited on; a background image or gradient,
   or an image element, on the way is a stop. Ancestors are in that stack,
   and so is a scrim from another branch of the tree. Off the viewport the
   stack is empty and the ancestors stand in, as before. Le Monde's "Reject
   all cookies" is no longer failed at 1.14:1 on a white nobody sees: under
   its translucent scrim the stack reaches a photo, so it is set aside as
   text on an image, which is what the pixels there are.

Observed and left alone: the status the app returned in the instant
after launch, while nine tabs were restoring, paired a phone preset id
with a 1920×1080 viewport and empty URLs — a transient not reproduced
without a relaunch, noted for a run that starts one.
