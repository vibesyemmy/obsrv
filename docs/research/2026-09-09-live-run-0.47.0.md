# 0.47.0 driven against five more live sites

The sixth run, on a stack that is 0.47.0 end to end — the app relaunched
from the new DMG, the plugin updated, the session's MCP server started
after the publish — against nhs.uk (an accessibility-first public service,
as the control), zara.com (thin type over a location gate, then the UK
shop), ebay.co.uk (a dense retail grid under a consent layer),
theverge.com (hairlines and dark sections under ads that never finish
loading) and berkshirehathaway.com (the page with no viewport meta, this
time as a run site). espn.com got one regression probe first, since 0.47.0
exists because of it. Headless, live, and every surface. The site is the
fixture; this reports on the tool.

## Broke or misled, ranked

1. **The image rules judge width alone, so a cover-fit image is measured
   on the axis that happens to fit.** `cli/lint.ts` sets `ratio =
   naturalWidth / drawn.width` and nothing else. On ebay.co.uk at
   `android-65` a 960×331 file filling a 551×567 box was reported "upscaled
   1.15×"; under `object-fit: cover` the file is scaled by the larger axis,
   1134/331 = 3.4×, and under the default `fill` its height is stretched
   3.4× regardless. A fixture makes the other direction plain: the same
   960×331 file in three 551×567 boxes — `cover`, `fill`, `contain` — on a
   1x screen gets no finding at all, because 960/551 = 1.74 sits between
   the upscale tolerance and the 2× oversized threshold, while the cover and
   fill boxes are in fact upscaled 1.71× on their height and the contain box
   is drawn at 551×190 and downsampled 1.74× (rightly silent). The page can
   say what `object-fit` is; the judge should use both axes: for `cover`
   the larger drawn-over-natural ratio, for `contain` and `scale-down` the
   smaller, for `fill` the worse axis in each direction, for `none` no
   scaling.

2. **A measurement that refuses a cut load answers with Electron's own
   stderr first.** Lint on theverge.com at a 30 s budget errored as
   designed, but the MCP's error text was a kilobyte of
   `task_policy_set TASK_CATEGORY_POLICY: (os/kern) invalid argument`
   lines, a blocked tracking pixel's URL and an SSL handshake code, with
   the one sentence that matters — `obsrv: load did not finish within
   30000 ms … raise --timeout` — last. The 60 s attempt read the same. The
   CLI's own lines are prefixed `obsrv:`; the error should be those, with
   Chromium's chatter kept out of the caller's context.

3. **Page-space coordinates on a page drawn to fit, demonstrated.** The
   0.47.0 notes said `inspect { at }` and `highlight { space: "page" }`
   still read the page's own px on a no-meta page. On berkshirehathaway.com
   at `android-65`, `highlight` given the GEICO logo's own rect (452, 639,
   75×15, straight from the audit) answered `drawn: false` and "the page
   rect is off screen at the current scroll (0, 0)", for an element that
   is on screen: the app took 452 of the 360-wide screen instead of
   452 × 0.37 = 166. The same `layoutScale` the measurements now carry is
   the factor the mapping needs.

4. **`truncated.findings` counts a cut that never happened under
   `groupsOnly`.** The ebay audit with `groupsOnly: true` answered
   `findings: []` and `truncated: { findings: 17 }`: seventeen past a
   200-item list that was not printed. The audit and the lint both compute
   the cap's cut before the flag empties the list; with no list there is
   nothing cut, and the summary's `under` counts already say how many
   findings exist.

5. **The inspector says the layout-scale sentence twice.** Headless and
   live, the readout carries it in `readout.notes` and the MCP copies the
   readout's notes into the answer's `notes` as well, so every no-meta
   inspection reads the same 60 words twice.

## Fixed on `fix/image-fit-and-error-text`

1. **The image rules follow `object-fit`, on both axes.** The page reports
   how each raster is fitted into its box, and the judge scales the file the
   way Chromium does — a cover by its larger axis, a contain or scale-down by
   its smaller, a fill by each axis on its own, none not at all — then takes
   the axis scaled most: the most blurred for an upscale, the most softened
   for a downsample. The finding carries `objectFit`, the sentence names the
   fit and, for a fill that stretches, the axis and the other axis's factor.
   ebay.co.uk's hero now reads what it is; the fixture's cover and fill boxes
   are upscaled 1.71×, its contain box in a small slot is oversized 4.8×, and
   its none box is silent. An older app's reply without the field reads as
   fill, which is what the rule assumed before.

2. **A tool error is the CLI's own sentence.** The MCP strips the lines
   Chromium and Electron write to stderr — the `task_policy_set` log, the
   blocked-URL warning and its `--trace-warnings` hint, the SSL handshake
   line, `objc[…]` — before composing an error, and falls back to the raw
   tail only when there was nothing else. The Verge's refusal is now one
   sentence.

Observed and left alone: zara.com's location gate took the walk 3.5 s to
see the end of one screen (the image settle waiting on a hero that never
arrived); the same shop at a phone preset settled on a grey placeholder
hero, which is not one colour and so not blank, and is what `waitMs` is
for; theverge.com finished loading inside a 15 s snap budget and not
inside 30 s or 60 s measurement budgets on the same afternoon, which is
the ad network's doing, not the tool's.
