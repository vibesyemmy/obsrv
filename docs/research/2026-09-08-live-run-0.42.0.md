Build under test: installed app 0.42.0 (pid 22172), `getobsrv` 0.42.0 on npm, the
session's MCP tools running that published package, main HEAD 802dcca (the
0.42.0 tag). So this is the release, not a branch. The sites are fixtures; the

## What broke or misled, ranked

1. **Headless lint/report judge lazy-load placeholders as upscaled images.**
   apple.com headless lint at 1080p-24: `image-upscaled` ×19, each "1×1 px
   (the 1x candidate) drawn over 1250×1250 device px: upscaled 1250×". The same
   tab linted live, where the walk mounted the images: 0. The report is
   headless, so it would pin nineteen bogus images. Fix: walk before measuring
   headless too, or treat an `img` whose natural size is ≤ 1 px (or not yet
   `complete`) as unloaded and skip it with a count in `skipped`.
2. **`groupsOnly` still warns about the list it left out.** "82 more findings
   past the 200 listed; the summary counts them all" with `findings: []`
   (headless and live, HN). The CLI, which does list 200, is right; only the
   groups-only wording is wrong. The report shows the same line under a
   grouped table.
3. **Live snap reads `url` mid preset-flip.** `obsrv_snap` auto on the HN tab
   with `preset: android-65` returned `url: "about:blank"`, `loading: false`
   while its capture showed the loaded page; a bare drive status a moment later
   said HN. The preset flip reloads the tab; the status was read between
   about:blank and commit. Read it after the capture.
4. **A full-page PNG over 1.5 MiB stays on disk silently.** apple.com 1080p-24
   bands: 4.6 MB, not inlined, no note in the JSON though the tool text
   promises one. The 1.3 MB Wikipedia one inlined.
5. **Warnings repeat verbatim per band.** "page kept painting steadily…" twice
   on the usekolo full page; "full page: page kept painting…" twice per screen
   in its report. Say which band, or say it once.
6. **Audit rule gap** (`src/shared/audit.ts:132`): any `a` with
   `display: inline` is exempt as running text. HN's upvote arrow is an inline
   `a` with no text and a 10×10 block icon — a control — so the laptop audit
   counts 1 target and the phone layout (which makes it block) 31. An inline
   `a` with no text of its own but a sized child is a control.
7. **Concurrency.** The MCP server runs calls in parallel, one headless
   Electron each. Nine at once: two apple.com calls died with "load did not
   finish within 30000 ms"; alone, both passed. A queue or a concurrency cap,
   or at least a note in the error, would stop an agent blaming the page.

Observations, not bugs: headless snap JSON has no final URL, so a UA redirect
(Wikipedia → Minerva) is invisible except in the PNG; the live status `url` is
the native pane's committed URL, so with the target on a mobile UA it says
en.wikipedia.org while the target shows en.m.; full-page JSON does not say
which scroller it followed; the CLI lint has no `--groups-only`; Wikipedia's
sticky "Appearance" rail repeats in every band, by design (a side rail covers
no content).

## Agent control off

With the AGENT chip off and the consent bar unanswered, snap, audit and drive
in auto mode all came back `why: launch-timeout`: "Obsrv is running and was
asked whether to allow agent control, but nobody answered within 12 s".
control.json read `{enabled:false}` with no `declined` — the `not-asked`
stance. `declined` is only ever an answered "Not now" (control.ts:142), so:

- the skill and `server.ts:260` describe `declined` as "the user turned agent
  control off", which is not what produces it;
- the skill's advice on `launch-timeout` ("the next call usually finds it")
  sends an agent back to knock again, 12 s a time, at a bar nobody is
  answering. The unanswered-consent case deserves its own `why`, or the note
  should say not to retry;
- the drive error says "rendered headlessly" though a drive renders nothing;
- snap files the note under `warnings`, audit under `notes`.

The bar itself works: answered "Allow" inside the window, the same knock came
back `mode: live`, `navigated: true`, and control.json dropped its
`enabled:false` — one call from consent to drive.

"Not now" works too, with a wrinkle. The click on one knock landed after the
12 s deadline, so that call said `launch-timeout`; the app still wrote
`declined: true` to control.json (a sampler read it on every tick of the next
knock), and the two calls after answered `why: declined` at once without
launching or re-asking (`control.ts:263`). Twelve seconds is a short window
for a human to notice a bar and click; the late answer still governs, which is
the right outcome. The declined note reads "the user turned agent control off
in Obsrv" although the trigger was the "Not now" click; it does tell the agent
not to retry, which is what matters.
