# 0.52.0 driven against five more live sites

The ninth run, on a stack that is 0.52.0 end to end — the app relaunched
from the new DMG, the plugin updated, the session's MCP server started from
a fresh registry install whose Electron the server fetched itself at boot —
against etsy.com (a retail grid behind a bot wall), spotify.com (the web
player shell on desktop, a dark marketing page on a phone), rust-lang.org
(a plain documentation front page), apnews.com (news behind a consent wall
with 619 partners) and nasa.gov (an image-heavy institutional site, 15,000
px tall on a phone). Headless, live, and every surface. The site is the
fixture; this reports on the tool.

## Broke or misled, ranked

1. **A load that never finishes is an error for the audit and the lint, and
   a capture for the snap.** apnews.com's `load` event never fired behind
   its consent wall — not at 30 s, not at 60 s — because 619 partners' beacons
   keep it open. `obsrv_snap` captured the wall as it stood and said
   `unsettledReason: "loading"`. `obsrv_audit` and `obsrv_lint` refused:
   "obsrv audit failed (exit 1): load did not finish within 30000 ms — raise
   --timeout for the full load", advice that cannot help a page whose load
   never completes. The DOM was there to measure. The measurement should
   proceed on the page as it stands when the load budget runs out, carry a
   warning naming the cut load, and then have its own budget as it does
   after a normal load.

2. **"Nothing to measure" does not say the page is an iframe.** Etsy's
   DataDome wall, headless at android-65 and live in the app alike, answered
   0 targets and 0 text with "a page rendered by script that had not run
   yet, a bot wall, or an empty document" — while the snap shows a heading,
   a paragraph and a slider. `obsrv_inspect` at the slider found an `iframe`
   covering the whole viewport, 360×800. The measurement does not enter
   iframes, which is fine; the sentence should say that the visible page is
   one, with its coverage, so the reader knows the wall is not empty and the
   figures are not the page's.

3. **The walk is silent on an app shell where the capture speaks.** Spotify
   on desktop is the web player: `html, body { overflow: hidden }` with no
   scroller the walk could find. The full-page snap warned in a sentence;
   the audit and the lint answered `walked: { screenfuls: 0, atEnd: true }`
   and nothing else, which reads like a one-screen page. The walk should
   carry the same note when it found nothing to scroll on a page that hides
   its overflow — the follow-up from the app-shell work, still open.

Observed and left alone: the live app's persistent profile met the same
DataDome wall as the fresh headless profile, so a wall that keys on the
mobile UA is not something a profile can pass; a new tab opens with the
`reference` panel regardless of the tab before it, which is the documented
per-tab behaviour.

## Fixed on `fix/measure-what-loaded`

1. **A load the budget cut is measured as it stands.** The audit and the
   lint take the page as it is when `load` has not fired within `--timeout`
   (`timeoutMs`), as the snap already did, and their first warning says so:
   "load did not finish within 3000 ms: … — measured the page as it stood; a
   page still arriving shows more with a longer --timeout, a page whose load
   never completes (a beacon that never answers) does not". The measurement
   then has its own budget as after any load. A fixture served by a server
   that never answers one image pins it for both.

2. **"Nothing to measure" names the iframe.** The page scripts count the
   iframes in the viewport and how much of it they cover; an empty report's
   sentence ends "; an <iframe> covers 100% of the viewport, which the
   measurement does not enter — a bot wall or an embed, not a blank page".
   Headless and live alike; an older app's reply carries no count and gets
   no clause. A fixture that is one iframe over the viewport pins it.

3. **The walk says when it had nothing to scroll.** The walk step reports
   whether the document hides its overflow; when the first step lands where
   the page already was, on the root, with that flag, both walks add the
   capture's sentence: "this page hides the document's overflow and has no
   scrollable container in its light DOM, so the walk had nothing to scroll:
   content in an iframe, in a shadow root, or in a container that scrolls by
   transform … was not brought into view before measuring". The live app's
   scroll reply carries the flag from this release on. The
   `app-shell-unreachable` fixture pins it headless and live.
