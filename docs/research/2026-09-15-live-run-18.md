# Run 18: report and diff, read cold

Run 2026-09-15 by Rook for `b1-report-diff`, on `main` at e715604, **built
first**. Two surfaces run 17 excluded explicitly: `obsrv report` and
`obsrv diff`. Sites are the two shapes run 17 planned and never reached — a
retail image grid (`uniqlo.com/uk/en/men`) and a docs site with a sticky
sidebar (`docs.astro.build`) — plus a static local fixture as a control.

**Three findings. None is a limit behaving as designed; the limits were the
best-behaved thing in the run.**

## The pre-registered vacuity check, and its answer

Written before running anything: this run has *not* exercised the two surfaces
if every site returns empty findings, if `diff` errors on every page for a
reason unrelated to the page, if every finding is one `audit` already produced
and `report` merely re-displayed, or if I cannot quote a sentence only these
two surfaces emit.

**It was exercised.** uniqlo produced 21 audit findings and 1 diff finding at
laptop-768; `diff` completed on two of three pages and refused the third for a
stated reason; and all three findings below are about `report` and `diff`
specifically, quoting sentences no other surface emits.

## F1 — `diff` invalidates its band deltas and leaves its headline numbers standing

`uniqlo.com/uk/en/men`, laptop-768. The page never goes paint-quiet, and `diff`
says so:

> renders did not go paint-quiet (animation or video, or a load that never
> finished), so the two captures are different frames — **the band deltas
> below** are frame-to-frame noise, not evidence about rasterisation.

The scope is the problem. Printed **above** that sentence, in the same reply:

```
inkCoverage: { target: 0.4006, reference: 0.4997, delta: -0.0991 }
rows:        { target: 710,  reference: 1439,   ratio:  0.4934 }
```

Those are comparisons between the same two mismatched frames. A reader told the
band deltas are noise reasonably concludes the headline numbers are not.

**The control makes it sharp.** On a static fixture: `settled: true`,
`findings: []`, and `inkCoverage` and `rows` print in exactly the same shape. So
the only thing separating "these numbers mean something" from "these numbers
are noise" is one sentence that names the bands alone — and the numbers a
person would actually quote are the two it does not name.

## F2 — the report's central image is altered, and the sentence saying so is the only one that never reaches the artefact

Every `report` run prints this to stderr:

```
hid chrome stuck to the viewport for the bands after the first:
  div.template-base__nav-header (fixed, 64 px), div.home-template__mask (fixed, 96 px)
```

Two fixed elements, 160 CSS px between them, removed from every band after the
first of the full-page capture. That capture is what the report's *"Where the
problems are"* overview is built from — the page's central evidence, the thing
a designer looks at.

**It reaches nothing a reader sees**, confirmed three ways: absent from the HTML
(`"hid chrome stuck"` not in 1.9 MB of it), absent from `screens[].warnings` in
the JSON, and therefore absent from any MCP caller's reply.

The mechanism is exact and deliberate rather than an oversight:
`src/cli/warnings.ts`'s `warningSink` gives `warn()`, which pushes to the
machine-output list **and** prints to stderr. `human()` prints to stderr alone.
The stuck-chrome sentence and the band-count sentence use `human()`; the
truncation warning beside them uses `warn()`. So the two channels are a
classification, and these sentences were classified as narration.

**Everything in `warnings[]` does reach the HTML** — verified on the same page,
where the truncation, motion and paint-quiet warnings all appear. The artefact
renders its warnings faithfully. The defect is that this one never joins them.

On `docs.astro.build` the consequence is starker still: `screens[].warnings` is
`[]` for both screens while stderr carried two sentences per screen. An empty
warnings array reads as *nothing to say about this capture*. It fits that, and
it fits *the remarks went somewhere you cannot see* — the two-facts silence, in
the surface nobody had examined.

### The half that makes this a correctness problem, not a reporting one

Found by Henry after this run was written, and it is the sentence that settles
the severity. `docs/compatibility.md`, contract 4:

> **Exit codes and stderr** — an exit code that changes meaning is breaking.
> Human-readable text on stderr is not a contract and may be reworded at any
> time; **if you are parsing it, parse the JSON instead.**

So the only place this fact appears is the one place the project's own policy
instructs callers to ignore. An agent following Obsrv's documented advice — read
the structured reply, never the prose on stderr — **cannot learn that 160 CSS px
were removed from every band of the image it is reasoning about.** The overview
is what findings are pinned to; a caller has no way to know it was edited.

That moves F2 out of "a warning is hard to find" and into "a warning the
documentation tells you not to look for". Every MCP caller is in that position
by construction, because an MCP client never sees stderr at all.

## F3 — a sentence with two prefixes, in the artefact

```
full page: warning: full page is 10374 CSS px tall; captured the first 12 bands …
```

The warning already begins `warning: full page is`; the report prefixes
`full page: ` when folding a capture warning into a screen's list. The result
says "full page" twice and carries a bare `warning:` mid-sentence. Visible in
the HTML, so a designer reads it. Cosmetic, and this project treats sentences as
the product.

## What held, and it is most of the run

- **Both documented `diff` limits refuse correctly and explain themselves.**
  A 3x preset: *"diff compares the target against a 2x reference downsampled
  onto the target's 1x grid, so it only supports 1x targets in v1 —
  'iphone-61' renders at 3x. Use a 1x preset (e.g. laptop-768, 1080p-24) or
  plain `obsrv snap` for dense presets."* A 4K preset names the axis cap and
  the preset's own dimensions. Someone who hit either by accident would know
  what to do. **Both exit 2** — the documented `ArgError` code — with empty
  stdout, and a good diff exits 0. Measured without a pipe, after `$?` after
  `tail` told me 0 the first time.
- **`report` names the comparison it did not do.** android-65 carries
  `diffSkipped: "a dense screen has no 1x-vs-2x comparison; the render itself
  is the evidence"`, and the HTML says the same under the heading rather than
  leaving the section empty.
- **The motion warning is a model sentence**: *"1 of the 217 elements
  re-measured had moved, by up to 17 CSS px in the 265 ms after the figures
  were taken … a repeat run will not agree on them."*

## What this run does not close

B1 stays open. This is two surfaces, not the criterion: nothing was run live in
the app, run 17's remaining sites are still unvisited, and `report`'s own
composition was read on two sites rather than many. Whether the *pins and crops*
on the overview land where the findings actually are was not checked — only
whether the page explains what it could not locate.
