# 0.53.0 driven against five more live sites, through the dev lane

The tenth run, and the first with the dev lane as the harness: the tools
answered from the shared checkout's own build (`main @ 6793319`, 0.53.0),
every result stamped with the build that produced it, no publish, no DMG,
no plugin update and no session restart between a change and a check.
Against arxiv.org (a plain academic index), reuters.com (a 19,287 px news
front page behind DataDome), wise.com (a marketing page whose full-page
capture changes the layout), w3.org (an old standards page) and
duckduckgo.com (a search home that renders dark on a phone). Headless,
live, and every surface. The site is the fixture; this reports on the tool.

## Held

- **The lane, as a working harness.** Every structured result carried
  `obsrv-dev lane: main @ 6793319 · server built 10:54:22 PM · <checkout>`
  in its notes, so which build answered was never in doubt — the thing
  0.53.0 added for exactly this run.
- **Live and headless agree.** arxiv.org at android-65: 17 targets, 12
  under 7 mm, and a lint of 7 contrast-on-panel findings plus 1 oversized
  image — the same from the CLI, the live window and the report. A diff
  of the page against itself came back clean.
- **The warnings that name their own distortion.** wise.com's full-page
  capture reported `layoutScale: 0.8824` and said the layout it measured
  is not the layout at the preset. reuters.com's walk stopped at 15
  screenfuls of a 19,287 px page and said so rather than implying it had
  reached the end; the snap named the DataDome wall it landed on.
- **The rules on real pages.** w3.org: one target under 7 mm, a 1.98 mm
  `®`, which is correct and worth reporting; nine oversized images on a
  page that predates srcset. duckduckgo.com: 8 of 8 targets over 7 mm, a
  10 px badge, and the dark phone page rendered and measured.

## Broke or misled, ranked

1. **One space in a page's markup loses the whole lint.** `obsrv lint
   https://www.reuters.com --preset 1080p-24` exits 1 with "the page did
   not answer the lint (it may have navigated away, or thrown while being
   measured)". Both halves of that sentence are false: the page answered,
   promptly and completely. Instrumenting the discarded reason (three runs,
   in a worktree) showed the ask returning a full report — 365 text
   elements, 49 images, nothing truncated — which `parseLintReport` then
   rejected, dropping all of it.

   The cause is one image. `parseSet` in `src/shared/lint.ts:337` splits a
   srcset on whitespace, with the comment "split on whitespace, since a
   data URL carries a comma". But a srcset written `url 60w,url 240w` —
   no space after the comma, which the HTML grammar allows and CDN markup
   commonly emits — tokenises as `["url", "60w,url", "240w"]`, so the
   descriptor becomes `60w,https://…` with the next URL glued onto it, and
   the trailing `240w` is taken for a URL. Reuters' resizer candidates
   come out 254 characters long. `parseLintReport` then measures every
   kept string against `MAX_INSPECT_TEXT = 200`, documented as the longest
   *text snippet* the inspector keeps, and returns null for the report as
   a whole. The producer already bounds the URL it sends
   (`chosenUrl.slice(0, 200)`, `src/shared/lint.ts:387`) but never bounds
   a descriptor, so the two sides disagree about what can arrive.

   Three defects sit on that path, each worth fixing on its own:
   - the splitter mis-parses a legal srcset, so even when nothing fails
     the reported candidates and chosen descriptor are wrong;
   - one over-long value discards an entire page's measurement rather
     than that one image's srcset detail — "dropped whole rather than
     patched" is right for an untrusted payload, but the unit being
     dropped is far too large;
   - the reason is discarded, so the CLI guesses, and guesses wrong.

   Pinned by two fixtures that differ by a single character: the srcset
   `url 60w,url 240w` exits 1, and the same page with a space after the
   comma exits 0. Reproduced 4/4 at 1080p before instrumenting (MCP twice,
   CLI twice, with and without `--no-walk`). The same page's `obsrv_audit`
   (144 targets) and `obsrv_inspect` succeed, because neither reads srcset.
   At android-65 the same lint exits 0 with the correct "nothing to
   measure" note — that run met the bot wall, so the images never
   appeared, which is why the failure first looked preset-dependent.

Observed and left alone: reuters.com serves the DataDome wall to the phone
preset and the article page to the desktop one, so the two presets measure
genuinely different pages; the walk's 15-screenful stop on a 19,287 px page
is the documented cap doing its job, not a defect.

## Fixed on `fix/srcset-and-measure-reason`

1. **A srcset is read as written, comma or no comma after it.** The page
   script's whitespace split now also separates a descriptor from a URL
   glued to it (`60w,https://…`), which is the only position a comma can
   end a candidate — so the commas inside a data URL are still left alone.
   Pinned in the browser, where the page script runs against real layout:
   the same two candidates come back whether or not a space follows the
   comma, and a data URL keeps its own commas either way.

2. **A malformed srcset detail costs that image its detail, not the page
   its lint.** A descriptor is short by nature ("60w", "2x"), so one past
   16 characters is dropped on its own, as is a `chosen` past it and any
   candidate beyond the twelve the page sends. Everything that is the
   measurement — a box, a colour, a font size, a natural size — is still
   refused whole, and the tests say so in the same breath.

3. **A refused report says it was refused.** `TargetSource` remembers that
   an ask answered and its report did not pass checking (`unparsed`, beside
   `answered`, `timeout` and `failed`), and the CLI and the running app both
   say that instead of guessing: "the page answered the lint, but the report
   did not pass checking on the way in …". Pinned end to end for the CLI and
   for the live app, on a fixture whose id is longer than any report keeps.

The fixture `srcset-no-space.html` is reuters.com's markup in miniature: it
exits 0 now and exited 1 before, on the same build that measures it.
